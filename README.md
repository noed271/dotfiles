# dotfiles

Hyprland rice, managed with [GNU Stow](https://www.gnu.org/software/stow/).
Each top-level directory is a **stow package** whose contents mirror the tree
under `$HOME`. Stowing a package symlinks its files into place.

## Layout

```
~/dotfiles/
  hypr/   waybar/  rofi/  kitty/  swaync/  dunst/  wofi/
  btop/   cava/    fastfetch/  nvim/  yazi/  wal/
  matugen/      # color templates + config.toml (the source of all theming)
  localbin/     # ~/.local/bin scripts (custom commands)
  wallpapers/   # ~/.config/wallpapers
```

A package `foo` contains e.g. `foo/.config/foo/...`, so
`stow foo` (run from this dir) links it to `~/.config/foo/...`.

## Install (new machine)

```bash
# 0. Broadcom wifi (MacBook): the proprietary driver isn't installed yet, so
#    there's no network. Do this FIRST over USB tethering or ethernet:
sudo pacman -S --needed broadcom-wl linux-firmware-broadcom

# 1. Reinstall every package recorded in pkglist.txt (hyprland, waybar, etc.)
sudo pacman -S --needed - < pkglist.txt

# 2. Symlink the configs
sudo pacman -S --needed stow
git clone <repo> ~/dotfiles
cd ~/dotfiles
./install.sh          # stow every package with --no-folding

# 3. Regenerate colors
matugen image ~/.config/wallpapers/<one>.png
```

### pkglist.txt — package manifest

`pkglist.txt` is a plain list of explicitly-installed packages (one per line),
produced with `pacman -Qqe`. It's the package-level counterpart to the dotfiles:
configs are tracked here, and pkglist.txt records *which software* those configs
belong to. Reinstall the whole set with `pacman -S --needed - < pkglist.txt`
(`-` reads names from stdin). Refresh it after installing/removing packages:

```bash
pacman -Qqe > ~/dotfiles/pkglist.txt && cd ~/dotfiles && git add pkglist.txt && git commit -m "Update pkglist"
```

> Broadcom note: `broadcom-wl` is in pkglist.txt, but on a fresh install you
> can't run pacman without network, and the wifi needs that driver — hence
> step 0 over a wired/USB connection before step 1.

## Generated vs tracked

Theming is driven by **matugen templates** in `matugen/.config/matugen/templates/`.
matugen writes color files into each app on every wallpaper change. Those
**outputs are NOT tracked** (see `.gitignore`) — they are reproduced from the
templates, so only the templates need versioning:

| Generated (ignored)                     | Source (tracked)                    |
|-----------------------------------------|-------------------------------------|
| `hypr/colors/colors.conf`               | matugen template `hyprland-colors.conf` |
| `waybar/colors.css`                     | matugen template `colors.css`       |
| `waybar/style.css`                      | generated by the mode system        |
| `kitty/colors/colors.conf`              | matugen template `kitty-colors.conf`|
| `rofi/colors/colors-matugen.rasi`       | matugen template `rofi-colors.rasi` |
| `swaync/colors-swaync.css`              | matugen template `colors-swaync.css`|
| `btop/themes/matugen.theme`             | matugen template `btop.theme`       |
| `~/.config/starship.toml`               | matugen template `starship-colors.toml` (not packaged) |

`waybar/colors-waybar.css` is hand-maintained and **is** tracked.

## Mode system (Super+Shift+F)

`localbin/.local/bin/focus-mode` switches Normal / Focus / Zen by rewriting the
`source =` line under the `# HyprMod managed settings` marker in
`hypr/.config/hypr/hyprland.conf` and regenerating waybar's `style.css`.
Mode definitions: `hyprland-gui.conf` (Normal), `focus-mode.conf` (Focus),
`super-focus-mode.conf` (Zen).

## Adding a file

Put it under the matching package (`<pkg>/.config/<pkg>/...`) and run
`stow --no-folding <pkg>`. To remove links: `stow -D <pkg>`.
